# 脚本与工作流

根级 `scripts/*.mjs` 只做编排与 evidence adaptation；core 业务规则留在 Rust/workspace 模块，共享 gate 逻辑集中在 `scripts/testing/quality-gates.mjs`。

## 主要入口

| 脚本 | 职责 |
| --- | --- |
| `scripts/run-core-scenario-acceptance.mjs` | 读取显式 plan/evidence，校验 9/9 scenario identity，调用 `knowledge-quality-gates.v2` 并输出唯一 summary/exit |
| `scripts/run-test-projects.mjs` | `run_test_projects_baseline` baseline_guard；报告 batch init failure/diagnostic，不冒充 primary gate |
| `scripts/test-wiki-lifecycle.mjs` | `lifecycle_baseline` baseline_guard；按 assertion owner 输出 formal gate failures 和未覆盖面 |
| `scripts/collect-reference-project-reports.mjs` | `reference_fidelity_primary` 的指标/evidence adapter；通过必填 `--acceptance-plan <plan.json>` 注入 fixtures、阈值和 required companions |
| `scripts/run-tests.mjs` | 工作区测试编排 |
| `scripts/build-dist.mjs` / `scripts/publish-packages.mjs` | 分发与发布编排 |

## 共享模块

| 模块 | 责任 |
| --- | --- |
| `scripts/testing/core-scenario-acceptance.mjs` | 9 场景 matrix 与 Acceptance Plan factory |
| `scripts/testing/quality-gates.mjs` | gate registry、single-owner failure 聚合、coverage、overall decision 和退出码 |
| `scripts/testing/helpers.mjs` | 进程、并发、测试 runner 与文件系统辅助 |

## Adapter 规则

- adapter 只产出 `gate_results/failures/diagnostics/scenario_results`，最终 decision 由共享 kernel 计算。
- formal/primary gate 可以拥有 failure；baseline_guard 只能引用已有 failure。
- 短路、全跳过、零样本和 required 未执行必须保留 `not_covered`，整体为 incomplete。
- CLI 默认使用 summary 的 0/1/2 退出码；报告命令只有显式 report-only 才允许以 0 退出非 pass 结果。
- primary fixtures、阈值和 companion gates 必须来自调用方 plan，不得在共享脚本中固定。

## 维护要求

- 新增场景先更新 matrix/plan contract，再补 adapter 或 Runtime evidence。
- 修改 gate 语义时同步更新 [测试与验收](./01-测试与验收.md) 和 `workflow-verification` capability。
- 不把 debug trace、临时 fixture 输出或 change 报告写入 Wiki。
