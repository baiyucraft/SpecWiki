# 参考实现边界

## 当前参考

| 来源 | 证据位置 | 目标落点 | 采用方式 |
| --- | --- | --- | --- |
| 本机 `@uni-sw/unispec@0.1.0` | 本机已安装 package | Lite 的 TypeScript `.spec` workflow 与 asset ownership | 改写实现，不直接复制源码或模板正文 |
| 仓库 `unispec-*` Skills | `.agents/skills/unispec-*` | `wiki-*` Skills 的阶段职责、前置条件和暂停边界 | 改写借鉴，不作为产品执行依赖 |

SpecWiki Lite 的最终 authority 是本仓库当前的 TypeScript core、`packages/spec-wiki-lite/assets/**`、CLI 测试和 Wiki。参考来源不能覆盖已经确认的 Codex-only、`.wiki + .spec + .agents/skills` 产品边界。

## 产品与仓库治理的区别

- 本仓库可以继续使用 `unispec-*` Skills 管理 SpecWiki Lite 自身开发。
- 安装到用户项目的是 `wiki-continue/explore/propose/design/plan/apply/review/archive`。
- Lite 使用自己的 metadata、stage、artifact registry、validation 与 archive 实现。
- `wiki-*` Skills 可以借鉴 UniSpec 的职责分层，但不能调用外部 package 充当产品内核。

## 引用要求

任何新参考都必须同时记录：

1. 来源名称、版本和可复核位置；
2. 要影响的 Lite 模块、资产或测试；
3. 采用方式是直接迁移、改写还是仅借鉴；
4. 与当前总体设计、路径安全和 ownership 规则的冲突检查。

未写清来源、目标落点和采用方式的内容不得进入实现。直接迁移必须额外核对许可证、版本固定和后续维护责任。

## 不迁移内容

- 不直接复制参考 package 的源码、模板正文或产品命名。
- 不把参考 package 的 CLI 当作 Lite 的公开入口。
- 不建立第二套 metadata schema、Skills 目录或归档流程。
- 不把未验证的参考结论写成当前实现事实。
- 不因采用参考而改写历史 `.spec/archive/**`。

当前架构边界见 [总体设计](../06-设计文档/00-总体设计.md)、[Lite 内核设计](../06-设计文档/01-Lite内核设计.md) 和 [Agents 设计](../06-设计文档/02-Agents设计.md)。
