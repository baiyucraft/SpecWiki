# 常见问题

## `init` 会写入什么？

`spec-wiki-lite init` 创建 `.wiki`、`.spec/changes`、`.spec/archive` 和 `.agents/skills`，写入 package 登记的 Wiki 基线与八个 Skills。它不会扫描源码，也不会创建隐藏的数据副本。

## 为什么只支持 Codex？

Lite 将 `.agents/skills` 作为唯一、可版本控制的 Agent 资产位置。`--host` 只接受 `codex`，避免为不同宿主维护重复模板、hook 或 settings。

## `init` 或 `update` 会覆盖我的页面吗？

不会。ownership 规则是：

- `scaffold` 和未登记的用户页面永不覆盖；
- `managed` 基线默认保留本地内容，只有 `--force` 才恢复 package 版本；
- `skill` 每次同步到当前 package 版本。

建议在自有栏目中创建 `INDEX.md` 和 `NN-主题.md`，并从上级索引建立相对链接。

## `status` 的 ready 代表什么？

`ready` 表示 Wiki 静态检查通过、八个 Skills 已安装，并且 active changes 没有校验阻断。它不代表源码内容已被自动分析，也不能替代 Agent 对当前代码的直接核验。

## `.wiki` 与 `.spec` 有什么区别？

- `.wiki/` 只保存稳定、当前有效的项目说明和公开契约。
- `.spec/changes/**` 保存 proposal、design、测试计划、任务和 review 证据。
- `.spec/archive/**` 保存完成后的 change 历史，不把报告正文复制进 Wiki。

## 为什么严格校验不能归档？

先执行：

```bash
spec-wiki-lite validate <change-id> --strict --json
```

检查 stage 所需 artifact、metadata 一致性、parent/child 状态，以及 `review-report.md` 和 `test-report.md` 的 `scope: full` 与 pass 证据。修复阻断问题后再归档。

## 本仓库使用的 UniSpec 与 Lite 产品是什么关系？

本仓库开发过程仍可使用 `.agents/skills/unispec-*` 管理自身 change；发布给用户的是 `wiki-*` Skills 和 SpecWiki Lite 自有的 TypeScript `.spec` 工作流。Lite 不依赖外部 UniSpec 命令执行日常操作。
