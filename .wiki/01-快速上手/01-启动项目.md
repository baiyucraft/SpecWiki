# 启动项目

SpecWiki Lite 没有需要常驻的服务。安装 CLI 后，直接在目标仓库运行命令。

## 初始化目标仓库

```bash
spec-wiki-lite init --host codex
```

也可以指定目标路径：

```bash
spec-wiki-lite init ./my-project --host codex
```

`init` 创建 `.wiki`、`.spec/changes`、`.spec/archive` 和 `.agents/skills`，随后返回资产同步结果与项目状态。`.wiki` 初始包含 conventions、project、development、architecture 和 reference 五个栏目；内容页是可直接填写的 scaffold，不包含推断出来的项目事实。`--host` 只接受 `codex`；不传时也默认使用 Codex。

初始化后，八个 Skills 位于：

```text
.agents/skills/wiki-continue/SKILL.md
.agents/skills/wiki-explore/SKILL.md
.agents/skills/wiki-propose/SKILL.md
.agents/skills/wiki-design/SKILL.md
.agents/skills/wiki-plan/SKILL.md
.agents/skills/wiki-apply/SKILL.md
.agents/skills/wiki-review/SKILL.md
.agents/skills/wiki-archive/SKILL.md
```

## 日常检查

```bash
spec-wiki-lite status
spec-wiki-lite status --json
spec-wiki-lite update
```

`status` 只读检查 Wiki 静态结构、Skills 安装状态和 active changes。`update` 与 `init` 复用同一资产同步器：Skills 始终更新，受管基线仅在 `--force` 时覆盖，脚手架和用户页面始终保留。

## Change 操作

```bash
spec-wiki-lite show my-change
spec-wiki-lite show my-change --artifact design
spec-wiki-lite validate my-change --strict
spec-wiki-lite archive my-change
```

`archive` 只接受无阻断问题且具备 full/pass review、test 证据的 change；目标目录已存在时不会覆盖。

## 从源码运行

```bash
pnpm --dir packages/spec-wiki-lite run build
node packages/spec-wiki-lite/bin/spec-wiki-lite.js --help
```

源码入口和全局安装暴露同一组命令，不提供旧命令别名。
