# 启动项目

`spec-wiki` 没有长期运行的本地 Web 服务。日常启动主要是执行 CLI、构建产物或运行测试。

## 从源码运行 CLI

先构建：

```bash
pnpm run build
```

再查看 CLI 帮助或执行命令：

```bash
node dist/spec-wiki/bin/spec-wiki.js --help
```

## 统一 init

| 命令 | 作用 | 是否生成 runtime |
| --- | --- | --- |
| `spec-wiki init --host codex --repo-root .` | 初始化 SpecWiki：安装宿主 bootstrap 资产、扫描仓库、建立 repo-local knowledge runtime 和 Agent 入口 | 是，内部完成 |

Codex 是唯一 reference host，因此快速上手与默认设计验证优先使用 `--host codex`。显式选择 Claude 或 CodeBuddy 仍受支持，但它们属于 compatible projection。

初始化后的真实 skill 路径为：

```text
.codex/skills/wiki-<action>/SKILL.md
.claude/skills/wiki-<action>/SKILL.md
.codebuddy/skills/wiki-<action>/SKILL.md
```

本次 Wiki 文档整理是 docs-only pass，不等同于执行完整 `spec-wiki init`。

## 常用 lifecycle 命令

```bash
spec-wiki status --repo-root .
spec-wiki query "runtime" --repo-root .
spec-wiki update --repo-root .
spec-wiki sync --repo-root .
spec-wiki rebuild --repo-root .
```

`status / query / update / sync / rebuild` 是初始化后的后续维护动作。需要长流程机器 transport 时，`update`、`rebuild` 可使用 `--bridge-stdio`；该参数表示基础 stdin/stdout forwarding，不代表 production `research_page` bridge 或 durable provider session 已启用。
