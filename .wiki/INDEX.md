# Wiki 初始化任务

本页是初始化任务页，不是最终 wiki 首页。当当前 tool 读取到本页时，应探索当前项目并初始化 .wiki 内容；完成后必须把本页替换为正常 wiki 入口。

**目标**

为当前项目生成长期可维护的 wiki 入口和基础栏目内容。

**输入**

- 当前项目文件结构
- README、package、构建配置、测试配置、部署配置
- src / app / packages / docs 等源码与文档入口
- .spec、.agents、已有 wiki 或临时文档
- 用户补充的项目背景和维护要求

**步骤**

1. **判断信息是否足够**

   如果项目目标、主要技术栈或运行方式无法判断，先问一个会阻塞初始化的问题。

2. **探索项目现状**

   按需读取，不要无差别扫描全仓库。优先使用当前 tool 或运行环境提供的专责调研 agent 并行调研：

   - 项目定位、目标用户和核心能力
   - 技术栈、构建、测试、运行入口
   - 主要模块、边界和数据流
   - CLI / API / UI / 配置等对外方法
   - 已有文档、规范和临时设计稿

3. **填充栏目 INDEX.md**

   更新每个栏目下的 INDEX.md，将其中的 <占位内容> 替换为当前项目事实。

4. **补充快速上手页面**

   按项目情况在 .wiki/01-快速上手/ 下创建或补充：

   - 00-环境准备.md
   - 01-启动项目.md
   - 02-构建项目.md
   - 03-常见问题.md

   不适用的页面可在 .wiki/01-快速上手/INDEX.md 中标记原因，不要硬造内容。

5. **按需生成模块指南**

   如果项目存在清晰模块、包、子系统或应用边界，在 .wiki/03-模块指南/ 下按模块创建目录。每个模块目录建议包含：

   - 00-模块定位.md
   - 01-入口与目录.md
   - 02-常见开发任务.md
   - 03-验证与排查.md
   - 04-模块特有约束.md

6. **按需生成对外方法**

   如果项目存在 public API、CLI、SDK、配置契约或对外使用方式，在 .wiki/04-对外方法/ 下按包、命令或能力创建目录。目录中按需包含：

   - 安装与版本策略
   - 包入口
   - API
   - 场景示例
   - 故障排查
   - 公开契约约定

7. **按需新增其他 wiki 页面**

   仅为长期有价值的信息创建页面，例如模块说明、部署说明、测试指南、接口说明、运维约束等。不要把临时探索过程写入 wiki。

8. **恢复本页为正常 wiki 入口**

   完成初始化后，删除本任务说明，将 .wiki/INDEX.md 改为当前项目的正常 wiki 首页。首页至少包含：

   - 一级目录
   - SSOT规则
   - 按任务导航
   - 按模块或包导航
   - 文档约定

   用下面模板整体替换 .wiki/INDEX.md 的全部内容，不保留本初始化任务说明。

   ~~~md
   ---
   title: <项目名称> Wiki
   description: <项目一句话定位>
   updated: <YYYY-MM-DD>
   owner: <维护方>
   ---

   # <项目名称> Wiki

   <项目一句话定位，说明这个 wiki 服务谁、解决什么问题。>

   ## 一级目录

   | 目录 | 用途 |
   | --- | --- |
   | 00-文档约定 | <文档边界、页面模板和开发规范入口> |
   | 01-快速上手 | <首次接手项目的最短路径> |
   | 02-开发指南 | <项目通用开发流程、质量门禁、构建发布和架构约定> |
   | 03-模块指南 | <模块、包、子系统或应用边界；不适用时说明原因> |
   | 04-对外方法 | <CLI、API、SDK、配置契约或公开使用方式；不适用时说明原因> |

   ## SSOT规则

   - <长期文档、临时材料、change artifact 和代码事实的边界>
   - <各栏目之间禁止双写的规则>
   - <引用其他栏目时只写摘要和回链的规则>

   ## 按任务导航

   | 任务 | 阅读入口 |
   | --- | --- |
   | <任务名称> | <推荐阅读页面或目录> |

   ## 按模块或包导航

   有清晰模块、包、子系统或应用边界时填写：

   | 模块或包 | 用途 | 阅读入口 |
   | --- | --- | --- |
   | <模块或包名> | <职责或定位> | <对应 wiki 页面> |

   无清晰模块或包时填写：

   - 不适用，原因：<说明原因>

   ## 文档约定

   - 边界与 SSOT 规则：<链接到 00-文档约定/00-边界与SSOT规则.md>
   - 页面模板：<链接到 00-文档约定/01-页面模板.md>
   - UniSpec 开发规范：<链接到 00-文档约定/02-UniSpec开发规范.md>

   ## 待确认问题

   - <仍需用户确认的问题>

   无待确认问题时删除本节。
   ~~~

**输出**

- 完成后的 .wiki/INDEX.md
- 完善后的各栏目 INDEX.md
- 按需新增的 wiki 页面列表
- 仍需用户确认的问题
