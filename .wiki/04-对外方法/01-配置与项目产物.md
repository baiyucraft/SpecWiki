# 配置与项目产物

## 环境

| 项 | 要求 |
| --- | --- |
| Node.js | `>=20.19.0` |
| 包管理 | npm、pnpm 或其他可执行 npm package bin 的工具 |
| 宿主 | Codex |
| 项目配置文件 | `.wiki/config.yaml` |

当前版本读取 `version` 与 `wiki.language`。语言同时控制 Wiki 的目录/文件/正文和 8 个 Skill 及 references 的正文；默认 `zh`。未来 LLM 配置继续扩展在同一文件；本版本不执行 provider 调用。

```yaml
version: 1
wiki:
  language: zh
```

## 项目目录

| 路径 | 用途 | 所有权 |
| --- | --- | --- |
| `.wiki/config.yaml` | Wiki/Skill 语言和未来 LLM 项目配置 | 用户维护；force 不覆盖 |
| `.wiki/INDEX.md` 与五个栏目索引 | 初始化任务、导航和可填写骨架 | scaffold；用户维护 |
| SSOT、页面模板、Lite 工作流 | 通用 Wiki 与 change 约定 | managed；`--force` 才更新 |
| `.wiki/**` 其他 Markdown | 正式长期页面 | 用户维护 |
| `.spec/changes/**` | Active change artifacts | `wiki-*` Skills 与用户维护 |
| `.spec/archive/**` | 已归档 change 证据 | archive 命令写入，不覆盖 |
| `.agents/skills/wiki-*/SKILL.md` 与 `references/**` | Repo-local Codex Skills、模板和 review standards | skill；随 init/update 更新 |

`.wiki` 与 `.spec` 都应纳入版本控制；`.agents/skills/wiki-*` 建议一并提交，使仓库内 Agent 合同可复现。

## 初始化和更新

`init` 与 `update` 共享同一资产 registry：

```text
scaffold -> 仅缺失时创建
managed  -> 仅缺失时创建，--force 时允许更新
skill    -> 每次同步到 wiki.language 对应的当前包版本
```

未登记的 `.wiki` 文件和 Skill 用户扩展始终保留。Wiki 语言切换先预检 scaffold/managed 登记文件，只迁移未修改模板；Skill 登记文件因 package-owned 语义直接在同一事务中覆盖为目标语言。冲突、无效配置或路径逃逸失败关闭。根初始化任务由 Codex 按需执行，CLI 不扫描源码或自动生成项目事实。

## Change metadata

每个 active change 至少有 `.spec/changes/<change-id>/meta.yaml`：

```yaml
id: example-change
stage: exploration
deliveryShape: single-change
```

`stage` 与 required artifacts 的详细关系见[change 模块](../03-模块指南/03-change.md)。
