# SpecWiki Lite v0.1.0 发布合同

## 发布身份

| 项 | 合同 |
| --- | --- |
| npm package | `spec-wiki-lite@0.1.0` |
| executable | `spec-wiki-lite` |
| module format | ES module |
| Node.js | `>=20.19.0` |
| host | Codex |
| implementation | TypeScript |

本页是 v0.1.0 的长期发布 authority。`package.json` 提供当前版本事实；README、CLI help、staged package 和 Skills 必须与本页一致。

## 公开 surface

v0.1.0 只发布六个 CLI 命令：

```text
init
status
show
validate
update
archive
```

参数和退出码以[CLI](./00-CLI.md)为准。不存在未列出的公开命令或兼容别名。

Repo-local Agent surface 只包含：

```text
wiki-continue
wiki-explore
wiki-propose
wiki-design
wiki-plan
wiki-apply
wiki-review
wiki-archive
```

## 正式项目合同

- `.wiki/**` 是正式页面层，内容由用户与 Codex 维护。
- `.wiki/config.yaml` 选择 `zh|en` Wiki 与 Skill 正文，默认中文，并作为未来 LLM 配置扩展入口。
- `.spec/changes/**` 保存 active change artifacts。
- `.spec/archive/**` 保存不可覆盖的归档证据。
- `.agents/skills/wiki-*` 是 Codex 阶段工作流入口，每种语言包含 8 个 `SKILL.md` 与 16 个登记 references。
- `init/update` 只同步 registry 中的资产，并遵守 scaffold、managed、skill 所有权。
- `status` 只做确定性文件检查；`show/validate/archive` 共享 stage 与 artifact registry。

## 发布制品

Staged npm package 必须包含：

```text
bin/**
dist/**
assets/**
README.md
LICENSE
package.json
```

发布包不得依赖仓库外的本地可执行文件。`assets/**` 必须包含中英文 Wiki scaffold、旧英文 migration baseline，以及 `assets/skills/{zh,en}` 中每种语言 24 个完整 Skill/reference 源文件。安装路径不带 locale，语言由 `wiki.language` 选择。

## 验证证据

可接受的 v0.1.0 验证至少包括：

- 包级 TypeScript build 通过。
- 包级单元测试通过。
- 根级当前产品面、CLI 和 distribution contract 测试通过。
- staged package 的 manifest、README、help、assets 与源码 authority 一致。
- staged tarball 分别完成默认中文、显式英文和 zh↔en update，且 status 验证 8 个 Skill 的完整登记树。
- `git diff --check` 无空白错误。

Build、测试、staging 或 publish dry-run 只证明候选制品满足相应门禁，不自动证明版本已经发布。只有 registry 返回的真实版本和发布记录才能作为 release evidence。

## 兼容边界

v0.1.0 是 Lite 产品线的首个合同版本。当前测试开发阶段不维护更早产品面的命令、参数、资产路径或持久化格式；任何新增 public surface 必须先更新设计、测试和本发布合同。
