# 核心场景

| 场景 | 用户目标 | 产品入口 | 验收证据 |
| --- | --- | --- | --- |
| CS-01 | 在空仓库建立指定语言的 Wiki 与 Skills | `init [--language zh\|en]` | 配置、同语言 scaffold、`.spec` 目录和八个 Skills 存在 |
| CS-02 | 安全刷新或迁移 package-owned 资产 | `update` | 读取 `.wiki/config.yaml`，ownership 与迁移预检生效，自定义页面保留 |
| CS-03 | 查看项目文档与 bootstrap 健康 | `status` | 语言、bootstrap、INDEX、frontmatter、链接、orphan 与 SSOT issue 可定位 |
| CS-04 | 查看 active change | `status/show` | stage、required artifact 与文件状态一致 |
| CS-05 | 验证 change 是否可推进 | `validate --strict` | blocking issues 和退出码稳定 |
| CS-06 | 由 Codex 分阶段维护 Wiki | `wiki-*` Skills | 每个 Skill 有前置、输入、输出、暂停和下一阶段 |
| CS-07 | 原子归档完成的 change | `archive` | dated target、不覆盖冲突、parent/child 一致 |
| CS-08 | 从发布包完成自举闭环 | pack + CLI | tarball 安装后中英文 init/status、bootstrap 完成与 change validate/archive 成功 |

## 共同边界

- Agent 按需读取仓库事实；产品不预计算或持久化源码派生数据。
- 用户页面由用户拥有，任何同步模式都不覆盖。
- 所有失败在写入前校验路径和 precondition；归档冲突不自动合并。
- human 与 JSON 输出表达同一结果，JSON 用于自动化门禁。

详细命令见 [CLI](../04-对外方法/00-CLI.md)，能力 requirement 见 [规格基线](../05-规格基线/INDEX.md)。
