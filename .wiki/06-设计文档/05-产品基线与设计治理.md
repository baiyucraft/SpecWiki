# 产品基线与设计治理

## 当前基线

| 域 | 当前标识 | Authority |
| --- | --- | --- |
| 产品 | SpecWiki Lite | [总体设计](./00-总体设计.md) |
| npm package | `spec-wiki-lite@0.1.0` | `packages/spec-wiki-lite/package.json` |
| CLI | `spec-wiki-lite` 六个命令 | [CLI](../04-对外方法/00-CLI.md) |
| 发布合同 | `v0.1.0` | [v0.1.0 发布合同](../04-对外方法/02-v0.1.0发布合同.md) |
| Capability | 四项 Lite baseline | [规格基线](../05-规格基线/INDEX.md) |

每个域只负责自身事实。版本号、文件存在或文档采纳不能自动证明构建、验证、发布或 registry 可用。

## 证据轴

```text
decision: proposed | adopted | superseded | withdrawn
implementation: none | partial | implemented
verification: none | partial | passed | failed
release: none | packed | published
```

- 当前 Wiki 描述 adopted authority。
- 源码与完成的 tasks 支撑 implementation evidence。
- full/pass review 和 test reports 支撑 verification evidence。
- tarball inventory 只证明 packed；publish 必须有独立 registry evidence。
- `.spec/archive/**` 保存历史证据，但不会自动成为当前设计。

## 完成规则

一个 change 只有同时满足以下条件才能归档：

1. tasks 与 checklist 全部完成。
2. 公开合同、源码和测试一致。
3. review 与 verification 均为 full/pass。
4. strict validate 无 blocking issue。
5. dated archive target 不冲突。

## 维护责任

| 变化 | 必须同步检查 |
| --- | --- |
| package 或命令 | manifest、README、CLI、发布合同、distribution tests |
| Wiki 结构规则 | inspector、capability、页面模板、快速上手 |
| change schema | core/change、Skills、UniSpec 规范、archive tests |
| Skill 内容 | package assets、安装副本、Agents 设计、asset tests |

本基线引用 UniSpec 的来源、落点和采用方式以 [总体设计](./00-总体设计.md) 的参考边界为准。
