# 扩展场景

## 可在现有边界内扩展

| 方向 | 前提 | 不变约束 |
| --- | --- | --- |
| 更多 Wiki issue 类型 | 有确定性规则和失败 fixture | `status` 不推断内容正确性 |
| 更多 managed baseline | ownership 与迁移行为可验收 | scaffold 和用户页面不覆盖 |
| 更丰富的 JSON 输出 | human/JSON 保持语义一致 | 不改变退出码类别 |
| 新 artifact 类型 | stage registry 与 Skills 同步更新 | show/validate/archive 共用 evaluator |
| 更强 multi-change 检查 | parent/child fixture 覆盖回滚 | 归档保持原子和不覆盖 |

## 需要独立 change 的方向

- 新宿主支持：必须定义独立资产位置、发现机制和验收，不影响 Codex 当前合同。
- 远端协作：需要身份、权限、并发冲突和服务可用性模型。
- 内容质量评分：需要可解释的评价标准，不能混入结构健康结果。
- 在线发布自动化：需要 registry 凭据、tag、provenance 与回滚策略。

## 明确非目标

- 不自动理解整个代码库并生成页面正文。
- 不保存源码派生数据库、关系图或隐藏文档副本。
- 不提供远端搜索、RAG、团队权限或托管服务。
- 不承诺未实际执行的平台安装结果。

扩展需求先进入 `.spec/changes/**`，经过 proposal、design、tests 和 review 后再更新当前 authority。
