# SpecWiki Lite 总体设计

## 产品定位

SpecWiki Lite 为 Codex 仓库提供可版本控制、可审查、可归档的项目文档，并编排两个外部认知工具。Lite 自身不解析或保存源码语义：CodeGraph 提供当前结构证据，AOCI 提供长期受治理语义，最终结论由源码、测试、`.spec` 与 `.wiki` 交叉验证。

```text
Codex
  -> .agents/skills/wiki-*
  -> spec-wiki-lite CLI
       -> assets: 同步模板与 Skills
       -> config: 读取 Wiki 语言并保留未来 LLM 扩展
       -> wiki: 静态检查 Markdown
       -> change: validate/show/archive .spec
       -> tools: 固定版本安装与官方 readiness 聚合
  -> CodeGraph: 当前符号、调用链、impact、affected tests
  -> AOCI-CODE: 长期职责、约束、Code/Database Cognition
  -> .wiki 正式页面
```

## 稳定边界

- `.wiki/` 是唯一正式文档内容层。
- `.wiki/config.yaml` 是 Wiki 语言和未来 LLM 项目设置入口；默认中文。
- `.spec/changes/**` 是 active change 证据，`.spec/archive/**` 是不可覆盖的历史证据。
- `.agents/skills` 是唯一 Skills 落点，只支持 Codex。
- `init/update` 按语言同步登记资产，语言迁移失败关闭，用户页面永不覆盖。
- `status` 检查语言、bootstrap、Wiki 静态健康、Skills、active changes，以及两套官方工具门禁。
- `init` 默认准备 CodeGraph 1.6.0 与 AOCI 0.1.0-rc12；一次性延后返回 not ready，外部失败不回滚已成功的核心资产。
- CodeGraph 与 AOCI 都不属于 Lite runtime；Lite 不复制索引、知识图谱、AOCI 状态机、数据库业务行或凭据。
- `show/validate/archive` 消费同一 stage 与 artifact registry。

## 技术结构

| 模块 | 责任 |
| --- | --- |
| `core/assets` | registry、ownership、原子同步 |
| `core/config` | `.wiki/config.yaml` schema、默认语言和保留写入 |
| `core/wiki` | Markdown/YAML 静态健康检查 |
| `core/change` | metadata、artifact、status/show/validate/archive |
| `core/path` | canonical id、lexical/realpath containment |
| `cli.ts` | 参数、human/JSON 输出、退出码 |
| `orchestration/tools` | 固定兼容清单、argv 安全命令、timeout 与有界输出 |
| `orchestration/codegraph` | 固定版本安装、Codex MCP、官方 JSON 索引健康；不保存 Lite 自有图数据 |
| `orchestration/aoci` | SHA-256 安装、init/scan/doctor、verify/check/Guide 与数据库条件门禁 |

详细设计见 [01-Lite内核设计](./01-Lite内核设计.md) 和 [02-Agents设计](./02-Agents设计.md)。

## 参考边界

UniSpec 来源为本机 `@uni-sw/unispec@0.1.0` 与当前 `unispec-*` Skills；目标落点为 TypeScript `.spec` workflow、asset ownership、Codex Skills，以及一次性 Wiki bootstrap 行为；采用方式为行为合同改写，不直接复制源码或模板正文。
