# SpecWiki Lite 总体设计

## 产品定位

SpecWiki Lite 为 Codex 仓库提供一层可版本控制、可审查、可归档的项目文档。它不解析源码语义，不保存代码图或隐藏知识层；需要实现细节时，Agent 直接读取当前源码与 Wiki。

```text
Codex
  -> .agents/skills/wiki-*
  -> spec-wiki-lite CLI
       -> assets: 同步模板与 Skills
       -> config: 读取 Wiki 语言并保留未来 LLM 扩展
       -> wiki: 静态检查 Markdown
       -> change: validate/show/archive .spec
  -> .wiki 正式页面
```

## 稳定边界

- `.wiki/` 是唯一正式文档内容层。
- `.wiki/config.yaml` 是 Wiki 语言和未来 LLM 项目设置入口；默认中文。
- `.spec/changes/**` 是 active change 证据，`.spec/archive/**` 是不可覆盖的历史证据。
- `.agents/skills` 是唯一 Skills 落点，只支持 Codex。
- `init/update` 按语言同步登记资产，语言迁移失败关闭，用户页面永不覆盖。
- `status` 检查语言、bootstrap、INDEX、frontmatter、链接、orphan、SSOT、Skills 和 active changes。
- `show/validate/archive` 消费同一 stage 与 artifact registry。

## 技术结构

| 模块 | 责任 |
| --- | --- |
| `core/assets` | registry、ownership、原子同步 |
| `core/config` | `.wiki/config.yaml` schema、默认语言和保留写入 |
| `core/wiki` | Markdown/YAML 静态健康检查 |
| `core/change` | metadata、artifact、status/show/validate/archive |
| `core/path` | canonical id、lexical/realpath containment |
| `cli.ts` | 参数、human/JSON 输出、退出码 |

详细设计见 [01-Lite内核设计](./01-Lite内核设计.md) 和 [02-Agents设计](./02-Agents设计.md)。

## 参考边界

UniSpec 来源为本机 `@uni-sw/unispec@0.1.0` 与当前 `unispec-*` Skills；目标落点为 TypeScript `.spec` workflow、asset ownership、Codex Skills，以及一次性 Wiki bootstrap 行为；采用方式为行为合同改写，不直接复制源码或模板正文。
