# 边界与 SSOT 规则

> UniSpec managed baseline
>
> 本页由 UniSpec 内置模板管理。`unispec init --force` / `unispec update --force` 会将本页恢复为当前版本内置模板。
> 项目特有规则不要长期写入本页，应新增项目专属页面并从本页回链。

本页定义项目 wiki 的信息边界和 SSOT（Single Source of Truth）规则。初始化 wiki 时，先用本页约束各类内容应该写在哪里，避免长期文档、临时材料和代码事实互相重复。

## 文档边界

| 类型 | 存放位置 | 说明 |
| --- | --- | --- |
| 长期知识 | `.wiki/` | 稳定的项目说明、开发约定、模块指南和对外契约索引 |
| 变更过程 | `.spec/changes/<change-id>/` | proposal、design、system-tests、tasks、review reports 等 change artifact |
| 已归档变更 | `.spec/archive/YYYY-MM-DD-<change-id>/` | 已完成 change 的历史记录 |
| 临时材料 | `.docs/` 或 `.tmp/` | 阶段性设计稿、验证记录、调试输出和一次性材料 |
| 代码事实 | 源码、配置、测试 | 行为、接口、配置默认值和运行入口的最终事实来源 |

## SSOT 规则

- `.wiki/` 记录长期可维护的知识，不替代源码、配置、测试和 spec artifact。
- 涉及 CLI、API、配置、协议、数据结构或运行行为时，事实来源优先指向源码、测试或正式规格。
- wiki 页面可以解释事实、组织入口和沉淀经验，但不要复制大段会随实现频繁变化的内容。
- 临时探索、未确认方案和一次性验证记录不要直接写入 wiki；完成后只迁移仍有长期价值的结论。
- `research/` 是按需辅助调研材料；只要调研结论会影响当前阶段 artifact，或对话上下文不足以稳定承载调研信息，就可以生成，但它不是 required artifact。
- 当同一信息出现在多处时，应在次级页面链接 SSOT 页面，不重复维护。

## 长文组织规则

长页面判定是维护 guidance，不是 CLI validate、archive 或 update 的门禁。以下信号提示需要整理：

- 页面约 250-300 行以上。
- H2 / H3 过多，阅读路径不清晰。
- 同一页面承载多个独立稳定主题。
- 维护者经常只引用其中某一节。
- 页面修改成本、冲突概率或导航成本明显升高。

只有当页面同时承载多个稳定主题，并且已经阻碍导航、维护或精确链接时，才应升级为目录结构。单一主题仍可维护时，优先保留单页，只整理标题和入口。

目录化优先使用以下结构：

~~~text
.wiki/<栏目>/<主题>/
  INDEX.md
  01-<子主题>.md
  02-<子主题>.md
~~~

规则：

- 每个新增目录必须有 `INDEX.md`。
- `INDEX.md` 只写范围说明、阅读路径、子页索引和事实来源链接，不复制源码、规格、配置或报告正文。
- 二级及更深目录只在信息架构稳定、每级都有清晰职责和 `INDEX.md` 时使用；不要因为单页稍长就制造目录层级。
- 子页可继承原页面的 `owner`、`package`、`audience` 和 `version_scope`，但 `source_of_truth` 必须按子页事实来源重新判断。
- 原页面若自指为 SSOT，拆分后只有真正承担事实来源的子页可继续自指；导航 `INDEX.md` 通常不作为业务、CLI、API 或配置事实的 SSOT。
- 整理或拆分页面时更新 `last_reviewed`。
- 拆分后同步更新父目录 `INDEX.md`、栏目 `INDEX.md`，必要时更新 `.wiki/INDEX.md`。
- 检查其它 wiki 页面、生成 Skill / reference 文案和测试断言中的旧链接；未完成的链接迁移必须记录为待处理 wiki 工作。

## 正式页面树规则

正式可见 Wiki 页面树只包括：

~~~text
.wiki/INDEX.md
.wiki/<栏目路径>/INDEX.md
.wiki/<栏目路径>/NN-主题.md
~~~

规则：

- 根入口和栏目入口使用 `INDEX.md`。
- 普通长期页面使用 `NN-主题.md`。
- 多级目录必须逐层提供 `INDEX.md`。
- runtime 隐藏目录、metadata、cache 和 knowledge artifacts 不属于正式可见页面树。
- `.wiki/pages/**` 不作为写入、查询、恢复、status、迁移或清理目标。

## 一级栏目边界

| 栏目 | 职责 | 不承载 |
| --- | --- | --- |
| 00-文档约定 | wiki 结构、页面模板、SSOT 和文档维护规则 | 具体业务、模块实现和对外接口正文 |
| 01-快速上手 | 首次进入项目的最短路径 | 深入开发规范、历史背景和完整 API 说明 |
| 02-开发指南 | 项目通用开发流程、质量门禁、构建发布和架构约定 | 模块特有例外、公开 API 正文和一次性探索记录 |
| 03-模块指南 | 模块职责、入口目录、模块特有约束、验证与排查 | 项目通用规范和公开接入示例全文 |
| 04-对外方法 | 面向使用者的 CLI、API、SDK、配置契约、示例和故障排查 | 内部实现细节、未公开模块约束和临时设计过程 |

如果某个项目没有模块、public API、CLI 或 SDK，对应栏目应在 `INDEX.md` 中说明不适用或保留占位，不要硬造内容。

## 禁止双写清单

- 不在快速上手中重复维护深入开发规范；快速上手只保留最短路径，并回链到开发指南。
- 不在模块指南中重复维护公开 API 参数表、完整示例或安装说明；模块指南只保留契约映射和回链。
- 不在对外方法中维护内部实现细节、模块分层规则或未公开约束；对外方法只面向使用者。
- 不在多个 wiki 页面复制同一份命令、配置默认值、接口字段或运行行为；这些事实应回链到源码、测试、正式规格或唯一 wiki 页面。
- 不把未确认假设、临时调研过程和一次性验证输出沉淀为长期结论。

## 正确写法

### 模块页引用通用规则

只写本模块差异，并回链到通用规则：

~~~md
本模块遵循项目通用测试门禁；模块特有验证入口见本页，通用测试命令见 [02-开发指南/测试或质量相关页面](../02-开发指南/INDEX.md)。
~~~

### 内部页引用公开契约

只写映射关系，不复制公开 API 正文：

~~~md
本模块提供 <公开能力> 的内部实现；使用方式、参数和示例以 [04-对外方法/<对应页面>](../04-对外方法/INDEX.md) 为准。
~~~

### 快速上手引用详细说明

只写最短步骤，把背景、边界和排障交给详细页面：

~~~md
首次运行执行当前项目快速上手页中的最短命令。环境变量、常见失败原因和平台差异见 [02-开发指南](../02-开发指南/INDEX.md)。
~~~

## 维护要求

1. 新增长期页面前，先确认它属于 wiki，而不是 change artifact 或临时材料。
2. 新增或移动页面后，同步更新所在目录的 `INDEX.md`。
3. 修改公开契约、模块职责或开发流程后，同步检查相关 wiki 页面是否需要更新。
4. 长页面整理或拆分时，同步处理 frontmatter、SSOT、反向链接和栏目索引。
5. 无法确认事实来源时，在页面中保留待确认项，不要把推测写成结论。
