# SpecWiki Lite 0.2.0: CodeGraph and AOCI-CODE dual cognition

## Problem

SpecWiki Lite currently uses CodeGraph only for precise structural analysis during the staged change workflow. The Wiki is authored by Codex from repository evidence rather than generated by CodeGraph. The product lacks a Git-reviewable, cross-session semantic cognition layer for responsibilities, constraints, and optional database Schema understanding. Replacing CodeGraph with AOCI-CODE or copying AOCI cognition into the Wiki would lose precise call-graph evidence and create competing sources of truth.

## Goals

- Require both CodeGraph and AOCI-CODE for every Lite project while preserving their distinct responsibilities.
- Install pinned versions by default, initialize their Codex integration, and allow one-run deferral for offline or CI environments while leaving the project not ready.
- Use AOCI's official governance gates for Code Cognition and require Database Cognition only after a database source is declared.
- Enhance the existing eight localized wiki Skills so AOCI supplies persistent semantic context and post-change maintenance while CodeGraph supplies precise structural and impact evidence.
- Publish the resulting public contract as spec-wiki-lite 0.2.0 with reproducible distribution verification.

## Non-goals

- Do not bundle AOCI or CodeGraph runtimes, databases, logs, sockets, or caches in the npm package.
- Do not copy AOCI's internal state machine, templates, source code, or formal cognition into .wiki or .spec.
- Do not read business rows or persist database credentials.
- Do not rewrite historical archives, publish npm, create a tag, or merge branches.

## Success Criteria

- init prepares pinned CodeGraph 1.6.0 and AOCI-CODE v0.1.0-rc12 and reports installation, MCP, index, Baseline, alignment, and next actions in stable output.
- --no-codegraph and --no-aoci perform no corresponding side effects but status.ready remains false; update --tools repairs or upgrades pinned tools.
- AOCI releases are selected by OS/CPU, checked against pinned SHA-256 values, and atomically installed into a stable user tool directory; invalid artifacts are never executed.
- status consumes official CodeGraph JSON and AOCI verify/check/Guide output so missing tools, incompatible versions, stale indexes, and unaligned governance are observable.
- Projects without database sources are not blocked by Database Cognition; after a source is declared, access, evidence/baseline, and cognition alignment gate readiness and archive.
- All zh/en Skills express the AOCI/CodeGraph stage division, and Wiki bootstrap uses AOCI global cognition plus CodeGraph/source/test verification.
- Package/root tests, lint, typecheck, build, pack, tarball smoke, strict validation, and git diff checks pass.

## Impact Scope

- CLI and orchestration: dual-tool install, status, pinned versions, download verification, and exit codes.
- Skills and templates: eight bilingual workflows plus AOCI research/design/review evidence.
- Wiki and docs: architecture, Agents, CLI, quick start, artifacts, tests, and the 0.2.0 release contract.
- Tests and distribution: command mocks, platform release fixtures, readiness gates, and tarball boundaries.

## Delivery Shape

single-change

CLI, status, Skills, Wiki, and the release contract form one independently reviewable 0.2.0 capability. Splitting them would leave intermediate public contracts inconsistent with readiness behavior.

## Risks

- Initial complete AOCI cognition requires an MCP-enabled Agent session after init and scan; a CLI child process cannot truthfully complete it.
- AOCI owns formal aoci*.txt assets, an AGENTS managed block, and machine-local Codex configuration; ownership and Git boundaries must not overlap Lite-managed files.
- AOCI verify/check may append local Ledger or Verify History even though they do not change formal cognition.
- Automatic external binary download introduces supply-chain, network, platform-selection, and atomic-recovery risks.
