# Python Review 规范

符合通用规范。本文件只补充 Python 异常、类型、async、集合迭代、路径、资源、日志、安全和测试相关的人工 review 重点。

## 适用范围

- Python 服务、CLI、库、脚本、测试、依赖和配置变更。
- 动态类型代码必须结合运行时边界、数据模型和测试证据审查。

## 必须同时读取

- `references/review-standard.md`
- 项目的 Python 版本、类型检查策略、依赖管理、测试框架、async / sync 边界和部署环境事实。

## Blocking / P0

- 异常必须捕获具体类型并保留上下文；禁止裸 `except:`、空 pass、过宽 try 块吞掉关键失败。
- 函数和公开契约应有类型注解；外部输入、配置、环境变量、文件内容和序列化数据必须用 dataclass / pydantic / 显式校验表达运行时边界。
- async 中不能直接调用阻塞 IO 或 `time.sleep`；任务取消、超时、锁和共享状态必须避免泄漏、阻塞和竞态。
- 文件、连接、锁、临时文件和上下文资源必须用 `with` / async context 管理；路径必须用 `pathlib` 或结构化 API，不能手拼危险路径。
- 大数据集不能一次性无界加载；遍历时不能直接修改集合；可变默认参数、闭包延迟绑定、`is` 比较值类型、float / datetime 比较等陷阱不能影响正确性。
- 不可信数据禁止 pickle 反序列化；日志、错误和配置不能泄露 token、密码、身份证等敏感信息。
- pytest 必须覆盖异常路径、边界输入、async 路径、资源释放和外部依赖 mock。

## Non-blocking / P1/P2

- 复杂列表推导式、过深嵌套、过大函数 / 文件、隐式公开 API 或模块职责不清。
- 日志未使用占位符、缺少业务标识或异常堆栈不足，但不影响当前功能。
- 依赖版本范围过宽、虚拟环境 / lock 策略不清或无人维护库带来维护风险。

## 建议工具化

- 配置 ruff / flake8、black、mypy / pyright、pytest、coverage、bandit、pip-audit / safety 和依赖锁定检查。
- PEP 8、导入排序、格式、简单类型错误、基础安全扫描、未使用代码和覆盖率阈值优先交给工具。

## 非目标

- 不人工替代 formatter、lint、类型检查和覆盖率工具。
- 不机械要求所有内部临时代码完全静态类型化；重点审查跨信任边界、公共契约和运行时数据。

## 常见误报

- 只因使用 `Any` 就给 blocking，而没有说明它跨越信任边界或隐藏真实失败。
- 只因没有 pydantic 模型就判错，而项目已有等价运行时校验。
- 把小规模列表处理误判为大数据内存风险。
